# MeetingAssistant V2 会议状态方案

日期：2026-09-21。实现分支：`v2`（工作区 `/.worktrees/v2`）。

## 已拍板

1. 页面保持 4 个 Tab：即时摘要、关键要点、待办事项、AI 建议。讨论要点写在「即时摘要」里面，不单独占 Tab。
2. 15 分钟校正的输入是三份材料：当前完整会议状态、最近 15 分钟转写、当前结论和待办已经引用的更早片段。
3. 关键词命中后只做标记。8 秒内的多次命中合并成一次分析。

其余保持：一份 Meeting State 驱动全部页面；增量更新、全量展示；左 65% 分析、右 35% 转写；问答是右下角浮动按钮加抽屉；条目带 `sources` 转写编号；旧会议缺新字段时原样显示；导出最后一版状态加完整转写；ASR 默认 Large v3 Turbo + CUDA，模型和设备仍可切换。

## 数据

一次模型调用产出整份状态：

```json
{
  "summary": "截至当前的整段概括",
  "topics": [{ "title": "京东账号注册", "points": [{ "text": "企业管理员分配权限", "sources": [18] }] }],
  "key_points": [{ "text": "采用企业统一账号", "sources": [18] }],
  "todos": [{ "content": "完成顺丰接口联调", "owner": "张明", "deadline": "本周五", "sources": [21] }],
  "suggestions": [{ "kind": "plan_change", "title": "计划可能发生变化", "quote": "会议原话", "detail": "模型判断", "sources": [12, 30] }]
}
```

`owner` 和 `deadline` 只有转写里明确说到才写具体内容，否则是「未明确」。`suggestions.kind` 只允许 `plan_change`、`missing_info`、`fact_check`。`quote` 是原话，`detail` 是判断。无效的 `sources` 在入库前丢掉。

## 更新

- 默认定时：沿用设置里的间隔，默认 30 秒。输入是上一版状态加尚未纳入的新转写。
- 提前触发：转写包含「决定、确定、负责、完成、截止、取消、改成、下周、周五」时标记一次。等待 8 秒；等待期间再次命中不另开调用。
- 校正：会议进行中每 15 分钟一次。最近 15 分钟按片段结束时间计算。更早、且被当前状态引用的片段另外附上。不重送整场全文。
- 模型失败时保留上一版，并在界面显示错误。转写继续。

问答不另写一份纪要。上下文是当前状态，加上与问题用词重合的转写（已引用片段加权），最多 12 条。没有证据时回答会议里还没有提到。对话只留在当次抽屉里。

## 界面

参考图提供卡片、下划线 Tab、深色录制条和「刚刚更新」的视觉。信息分区仍按已确认的方案，不把常驻聊天放进右栏，也不增加参考图里的分享、搜索、暂停和屏幕录制。

```text
┌──────────────────────────────────────────────┬─────────────────────┐
│ 会议标题                          刚刚更新   │ 00:24:31  录制中    │
│ 即时摘要 │ 关键要点 │ 待办事项 │ AI 建议    │ 音量条              │
│                                              │ 最新一句            │
│ ┌ 即时摘要 ───────────────────────────────┐ │                     │
│ │ 整段概括                                 │ │ 18:12               │
│ └──────────────────────────────────────────┘ │ 顺丰接口本周先完成  │
│ ┌ 1. 京东账号注册 ────────────────────────┐ │                     │
│ │ · 管理员分配权限          查看原文 ↗    │ │                     │
│ └──────────────────────────────────────────┘ │              问问 AI │
└──────────────────────────────────────────────┴─────────────────────┘
```

左栏约 65%，右栏约 35%。即时摘要 Tab 先是概括卡片，下面按编号列出讨论要点卡片。关键要点、待办、建议各自使用同一套来源跳转：点击后右栏滚到对应句并高亮。录制条只在右栏顶部显示计时、状态、音量和最新一句，下面仍是完整转写。

配色沿用现有界面：纸面 `#f7f8fa`，卡片白底，强调色 `#1f6b4e`，录制条 `#24312c`。

## 兼容与导出

旧摘要只有 `overview`、`key_points`、`decisions`、`action_items` 时，四个 Tab 显示当时已有的内容，不重新计算。导出在新状态下依次写即时摘要、讨论要点、关键要点、待办、AI 建议，然后是完整转写。
