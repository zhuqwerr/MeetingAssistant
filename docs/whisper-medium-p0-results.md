# Whisper Medium P0 性能检查

结论：**单路系统声音的速度门槛通过；完整 P0 暂不通过。** 本次检查在 Windows x64、AMD Ryzen 9 7945HX（16 核/32 线程）、15.7 GB 内存上进行。使用已有的真实会议系统声音 WAV，本地 Whisper Medium、CPU `int8`、当前应用的 200ms 输入/最长约 8 秒分段、中文识别配置。未发送音频或转写到外部服务。

| 项目 | 结果 |
| --- | ---: |
| 单路音频长度 | 600 秒 |
| 单路模型解码耗时 | 294.7 秒（音频时长的 0.491 倍） |
| 单路分段任务 / 保存片段 | 75 / 81 |
| 单路转写片段覆盖时间 | 约 580.7 秒；这是片段时间范围，不是人工标注准确率 |
| 单路片段结束到显示的 95 分位延迟 | 4.33 秒；不含最长约 8 秒的录音分块等待 |
| 单路末端延迟 | 4.20 秒，未随会议时长持续增长 |
| 模型加载及短片段识别峰值工作集 | 约 1.78 GB；未采集整场 10 分钟内存峰值 |

为检查混合采集的吞吐风险，将同一 60 秒语音分别当作麦克风和系统声音、交错送入同一个解码器：共 16 个任务，模型解码约 59.8 秒，模拟队列最大等待 6.5 秒、末端显示延迟 9.6 秒。两路同时连续发言时已接近该机器的实时吞吐上限。此短压测不能替代 10 分钟的真实双路会议验收，也不能推断普通低配 CPU 的表现。

在检查用户会议记录时另发现转写丢失：旧逻辑单独用 `no_speech_prob >= 0.6` 过滤，误删了置信度良好的真实语音。现已改为同时考虑文字置信度，真实音频 40 秒复测恢复了原先缺失的片段；完整测试 45 项通过。旧会议数据库没有被修改，旧摘要仍基于不完整转写。

完整 P0 的剩余条件：在目标硬件上完成至少 10 分钟真实麦克风+系统声音同步录制/回放，记录队列峰值、p95 延迟和全程内存峰值；人工核对一段标准原文以评估准确率与无声幻觉。完成前可以继续 Whisper/API 代码收敛，但不应宣布桌面版对双路会议已满足实时要求。
